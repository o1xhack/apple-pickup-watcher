# 独立浏览器查询（本机 US 版本）

桌面程序在未配置显式代理、且检测到已安装 Chrome/Chromium 时，使用独立无头浏览器执行库存查询。CLI 和其他调用者默认仍使用原 HTTP 客户端。`/api/state.queryTransport` 可核实当前选用的方式。

- 独立临时资料目录，不读取日常浏览器的账号、Cookie、购物袋，不执行购买操作。调试端口只绑定回环地址。
- 加载 Apple 商品页面，等待正常页面初始化，然后在该页面内通过 `fetch` 查询原 `pickup-message` 接口。型号、门店、去重、通知和 SQLite 历史继续走原逻辑。
- 合并 SKU 和附近门店，复用一个浏览器会话；保留原来的基础间隔、全局请求预算、失败退避和恢复策略。不会并发运行另一套库存监控，也不会在 541 后立即改走另一客户端追打。
- 页面握手失败和无法解析的数据均为未知，绝不视作无货。403/541 后丢弃浏览器会话；到原有冷却结束时才重新建会话探测。超时和取消会丢弃不确定的调试连接。
- 启动时从已有 SQLite 的网络生命周期记录恢复冷却截止时间、探测级别和恢复间隔。关闭、崩溃或更新不会成为跳过冷却的手段。不会修改用户设置中的基础间隔。
- macOS 新资料目录固定在 `<system cache>/apple-pickup-watcher/browser`，创建前校验 SSD UUID 和实际路径。没有正确 SSD 时报告未知，不回退内置盘。保存的进程归属只用于清理本程序遗留的浏览器，不操作用户浏览器。
- 显式代理配置继续使用原有 HTTP 传输，不忽略代理、不调整系统网络。未安装浏览器时默认保留原有查询方式。

真实浏览器不是不会被拦的保证。验收以原有节奏的真实响应、库存解析、历史写入及拦截率为准；单次 200 只证明当次可用，不代表长期解决。

离线测试覆盖地址限制、响应大小、541 状态保留、冷却重启恢复和解封后状态恢复。`local_browser_cdp_smoke` 是需手工运行的本地浏览器测试，只打开 `about:blank`，不请求 Apple。真实库存验证应复用运行应用的正常轮询，避免增加第二个轮询进程。
